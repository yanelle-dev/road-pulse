## 🎯 Роль

Вы помогаете развивать монорепозиторий «Дорожного пульса»:

- `app/` — Flutter-клиент (package `road_pulse`);
- `backend/` — сервис на Go (module `road_pulse/backend`): chi + pgx + PostGIS + JWT.

Пишите **чистый, короткий, масштабируемый** код. Не раздувайте scope. Не «улучшайте всё подряд» без запроса.

## ✅ Чеклист перед новой функцией

Перед тем как написать новый код, **явно** проверьте четыре пункта.

**1. Дублирование**  
Есть ли уже такой или почти такой код в `app/lib` или `backend/internal`? Поищите по имени, смыслу, endpoint, виджету. **Если есть — переиспользуйте, вынесите общее, не копируйте.**

> Известный долг: пороги силы (`> 20` / `> 30`) и порог скорости (20 км/ч) продублированы между клиентом (`app/lib/constants.dart`) и сервером (`internal/service/telemetry.go`). Внутри клиента общее место уже есть — новый порог добавляйте туда, а не в экран.

**2. Актуальность API**  
Используете ли вы современный API языка и пакетов проекта?

- Dart 3 и текущий Flutter: null-safety, `super.key`, `switch`-выражения, `withValues`, актуальные `LocationSettings`.
- Go 1.25: `errors.Is`/`errors.As`, обёртка ошибок через `%w`, `context` первым аргументом, chi вместо самодельного роутинга, `pgx/v5` вместо обёрток над `database/sql`.
- PostGIS: `ST_GeomFromText(..., 4326)`, `ST_ClusterDBSCAN`, SRID 4326 — не изобретайте свой формат координат.

Не тащите устаревшие паттерны «из памяти 2019 года».

**3. Можно ли короче?**  
Спросите себя: «Можно ли выразить то же яснее и короче?» Уберите лишние переменные, вложенность, обёртки «на будущее».

**4. Масштабируемость**  
Легко ли это расширить без копипаста?

- конфиг и константы вместо размазанного хардкода;
- одна ответственность на функцию;
- границы модулей из [ARCHITECTURE.md](./ARCHITECTURE.md): UI ≠ сеть ≠ датчики ≠ ORM ≠ HTTP.

Если хотя бы на один пункт ответ «нет» или «не уверен» — **остановитесь, поправьте подход**, потом пишите.

## ✨ Чистый код

### Делайте

- Имена, которые читаются без комментария: `sendDefect`, `ResolveLocationWKT`, а не `doStuff` или `data2`.
- Функция или метод делает **одно** дело.
- Маленькие понятные блоки, ранняя проверка ошибок (guard clauses).
- DRY: общая логика живёт в одном месте — `ApiService`, `internal/service`, `internal/osrm`.
- KISS и YAGNI: решайте текущую задачу, не стройте framework «на вырост».
- Ошибки в Go заворачивайте с контекстом: `fmt.Errorf("ошибка вставки в БД: %w", err)`.
- При росте сервиса новый сценарий оформляйте как `service` + `handler` + роут в `cmd/api/main.go`, а не раздувайте `main.go` логикой.
- При росте клиента новые экраны и сервисы делайте по образцу существующих, не сваливайте всё в `main.dart`.

### Не делайте

- **Лишние комментарии.** Комментируйте только *почему* (неочевидный trade-off, баг платформы), а не *что* — это видно из кода.
- Комментарии-нарратив (`// увеличиваем счётчик`), закомментированный мёртвый код, TODO без контекста.
- Дублирование UI, HTTP или формул «чуть-чуть по-другому» в двух файлах.
- Магические числа без имени (пороги, URL, timeout) — выносите в константы рядом с использованием или в конфиг-модуль.
- Новые зависимости без явной необходимости и без согласования с текущим стеком.
- Секреты, пароли и прод-адреса в новых местах: в MVP уже есть такой долг, не размножайте его.
- Моковые данные, замаскированные под реальные: если блок пока заглушка, это фиксируется в разделе «Известные ограничения», а не выдаётся за готовую функциональность.

## 🧱 Структура и границы слоёв

| Слой | Разрешено | Запрещено |
|------|-----------|-----------|
| `sensor_service.dart` | Датчики, пороги, трек, одометр, вызов API | Виджеты, тема |
| `api_service.dart` | HTTP, токены, буфер логов, локальная статистика и рейтинг | Бизнес-пороги акселерометра, разметка UI |
| `*_screen.dart`, `widgets/` | UI, локальный state, навигация | Дублировать POST/GET — только через `ApiService` |
| `achievement_service.dart` | Каталог, локальный прогресс достижений и накопленный пробег | Сетевые вызовы в обход `ApiService` |
| `internal/handler` | HTTP: разбор payload, коды ответов, middleware | SQL и бизнес-правила |
| `internal/service` | Бизнес-логика: нормализация, кластеры, OTP, JWT | Формирование HTTP-ответов |
| `internal/models` | DTO и JSON-теги | Логика и доступ к БД |
| `internal/database` | Пул `pgx`, схема и миграции | HTTP и бизнес-логика |
| `internal/osrm` | Внешний HTTP с timeout и fallback | Знание о схеме БД |
| `cmd/api/main.go` | Wiring, роуты, graceful shutdown | Копипаста SQL и логики из сервисов |

Соблюдайте существующие имена: **`app/`** (package `road_pulse`) и **`backend/`** (module `road_pulse/backend`). Прежнее имя проекта вычищено из идентификаторов всех платформ (Android — `com.roadpulse.app`); не возвращайте его в новых файлах сборки.

## 🛠️ Специфика стека

### Flutter / Dart

- `const`-конструкторы там, где это возможно.
- Отменяйте подписки и освобождайте контроллеры: `StreamSubscription`, `TextEditingController`, `AnimationController`.
- Не блокируйте UI-поток тяжёлой работой.
- Foreground task: entry-point `startCallback` и `SensorTaskHandler` остаются как есть — не ломайте контракт isolate (логи в UI идут через `FlutterForegroundTask.sendDataToMain`).
- Тема и цвета — только через `context.colors` и `AppTheme`; не хардкодьте цвета в экранах.
- Шрифты подключаются локально из `assets/fonts/`; не добавляйте `google_fonts`.
- Новые идентификаторы — на английском; пользовательские строки интерфейса — на русском, как в текущем UI.

### Go

- Явные типы на публичных функциях и DTO; JSON-теги — в `internal/models`.
- Работа с БД только через пул `*pgxpool.Pool`; `context.Context` — первым аргументом.
- Не логируйте секреты и полные персональные данные.
- Геометрия: WKT и `ST_GeomFromText(..., 4326)`, тип колонки `GEOMETRY(Geometry, 4326)`.
- Внешние HTTP-вызовы (OSRM) — с timeout и fallback: `osrm.Client.Nearest` возвращает исходные координаты, чтобы не терять попадание.
- Миграции идемпотентны (`CREATE TABLE IF NOT EXISTS`, `ADD COLUMN IF NOT EXISTS`) в `database.InitSchema`.
- Новые переменные окружения — через `internal/config` с осмысленным fallback; секреты в репозиторий не коммитятся.
- Пользователь берётся из JWT-контекста (`ContextUserIDKey`), а не из тела запроса. Записи, привязанные к пользователю, для `anonymous` не выполняются — это осознанное поведение `RecordDistance`, сохраняйте его явным.

### Одометр и статистика

- Пороги и ключи хранилища живут в `app/lib/constants.dart`, чистые формулы (рейтинг, бейдж, шаг одометра, даты, фильтры) — в `app/lib/calculations.dart`. Не копируйте их в экраны: на них уже есть тесты.
- Одометр считает только фоновый isolate (`_updateDistance` в `sensor_service.dart`), а экран «Запись» принимает готовый счётчик сообщением `TRIP:<метры>` через порт foreground-задачи. Не добавляйте второй счётчик шага.
- Источник правды по статистике — сервер: `GET /api/v1/auth/me` отдаёт пробег, число дефектов, рейтинг и процентиль, а клиент лишь синхронизирует серию дней и награды через `POST /auth/sync-stats` и прибавляет неотправленный буфер. Локальные формулы — только оффлайн-фолбэк.
- Рейтинг считайте в `internal/service/auth.go` по тем же слагаемым, что и на клиенте: иначе в системе появятся два разных рейтинга.
- `SharedPreferences` читайте через `freshPrefs()` из `fresh_prefs.dart` — он вызывает `reload()` и исключает рассинхронизацию между isolate и интерфейсом.
- Комментарии хранятся по `cluster_id`, который для ям равен `MIN(id)` точки кластера и меняется при слиянии кластеров. Не привязывайте к нему новые сущности, пока не появится постоянный идентификатор дефекта в БД.
- Пороги детектора живут в `constants.dart`, формулу порога (`bumpThresholdFor`) и разложение ускорения (`GravityFilter`) берите из `detection.dart`: ими пользуются и фоновый isolate, и осциллограф.
- Режим темы меняется только через `themeModeNotifier`; сохранение — `ThemeStore`. Не читайте и не пишите ключ темы из экранов напрямую.
- Ответы handler'ов формируйте через `respondJSON`/`respondError` из `internal/handler/http.go`, лимиты запросов — через `RateLimit` в `main.go`. Не отдавайте `err.Error()` внутренних ошибок клиенту.
- Коды OTP никогда не возвращаются в ответе API.
- SMS отправляйте только через `internal/sms.Provider` (`GateProvider` для боевой отправки, `MockProvider` для разработки); не вызывайте шлюз из handler'ов и не пишите коды в лог при боевом провайдере.
- Версия и номер сборки читаются из `pubspec.yaml` через `package_info_plus`. Не хардкодьте версию в интерфейсе, кроме резервной строки; номер сборки после `+` повышается монотонно.

## 📜 Контракты и документация

- Меняете request или response API → синхронно обновляете клиент (`api_service.dart` и экраны) **и** [README.md](./README.md) / [ARCHITECTURE.md](./ARCHITECTURE.md).
- Добавили, удалили или переименовали публичный модуль, функцию или пакет → обновляете `ARCHITECTURE.md`.
- Появилась заглушка в UI или обходное решение → строка в «Известные ограничения» в `README.md`.
- Не коммитьте: `app/build/`, `app/.dart_tool/`, `backend/bin/`, `backend/.env`, секреты и локальные ключи.

## 🔁 Порядок работы агента

1. Прочитайте задачу.
2. Откройте релевантные файлы и `ARCHITECTURE.md`.
3. Пройдите чеклист из четырёх пунктов выше.
4. Внесите минимальный diff.
5. Проверьте: нет дублей, имена ясные, нет мусорных комментариев.
6. При необходимости обновите документацию.
7. По возможности прогоните сборку, линт и smoke-проверку: `go build ./...`, `go vet ./...`, `flutter analyze`, `curl /health`.

## 🚫 Антипаттерны

```dart
// плохо: копипаста отправки дефекта прямо в экране
http.post(Uri.parse('http://...'), body: ...);

// плохо: комментарий «что»
// отправляем post запрос
await ApiService.sendDefect(...);
```

```go
// плохо: SQL и бизнес-правило прямо в обработчике
func (h *TelemetryHandler) PostTelemetry(w http.ResponseWriter, r *http.Request) {
    _, _ = h.pool.Exec(r.Context(), "INSERT INTO telemetry ...")
}

// плохо: потеря контекста ошибки
if err != nil {
    return err
}
```

```dart
// хорошо: переиспользование
await ApiService.sendDefect(lat: lat, lon: lon, speed: speed, force: force);
```

```go
// хорошо: слой сервиса и контекст в ошибке
locationWKT, geomType := s.ResolveLocationWKT(ctx, payload)
if err != nil {
    return nil, fmt.Errorf("ошибка подготовки геометрии: %w", err)
}
```

```text
# хорошо: комментарий «почему» (если он нужен)
# публичный OSRM ограничивает частоту запросов; при ошибке берём сырые координаты GPS,
# чтобы не потерять попадание
```

## 📣 Манифест

> Перед каждой новой функцией: **не дублируй → используй актуальный API → пиши короче → оставляй место для роста.**  
> Код должен читаться без комментариев. Документы — источник правды о структуре, код — источник правды о поведении.
