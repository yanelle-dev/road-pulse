# Дорожный пульс

Crowd-sourced карта дефектов дорожного полотна. Телефон в машине слушает акселерометр, привязывает удары к GPS и отправляет телеметрию; сервер нормализует силу удара по скорости, «прищёлкивает» точку к дороге, ведёт суммарный пробег и собирает общую карту подтверждённых дефектов.

## 🔰 О проекте

«Дорожный пульс» — клиент-серверная система из двух частей:

- **мобильное приложение** (Flutter, Android/iOS) — постоянно, в том числе в фоне, читает акселерометр и GPS, распознаёт удары и участки тряски и отправляет телеметрию на сервер;
- **сервис телеметрии** (Go + PostGIS) — принимает точки, привязывает их к дорожному графу, нормализует силу удара, кластеризует близкие попадания и отдаёт готовые дефекты для карты.

Общая карта строится совместно: два независимых водителя, попавших в одну яму, или три попадания в одну точку переводят дефект в статус подтверждённого.

### 🧭 Боль

- Водитель не знает, где на маршруте жёсткие ямы, пока не въедет.
- У города и сервисов нет «живой» карты дефектов покрытия — только разовые обходы и жалобы.
- Навигаторы оптимизируют время и пробки, но почти не учитывают качество асфальта.

### 💡 Решение

1. **Сбор.** Фоновая служба читает акселерометр (100 Гц) и гироскоп, раскладывает ускорение на вертикаль и горизонталь относительно гравитации (положение телефона не важно). Вертикальный удар выше порога, растущего со скоростью, открывает окно 600 мс; в окне отсеиваются торможение и манёвры, лежачие полицейские и резкое вращение телефона. Позиция берётся из потока GPS и экстраполируется на момент пика. Участки тряски определяются по RMS вертикали.
2. **Обработка.** Сервис проверяет вход, нормализует силу по скорости, привязывает яму к дороге через OSRM `/nearest` (участок `rough_road` — через `/match`) и сохраняет геометрию в PostGIS (`POINT` или `LINESTRING`). Повтор с тем же `client_event_id` не создаёт дубль.
3. **Кластеризация.** Близкие удары (радиус 12 м) объединяются `ST_ClusterDBSCAN`; кластер подтверждается при **≥ 2 уникальных пользователях** или **≥ 3 разных парах «пользователь-день»** (записи `anonymous` не считаются водителями). Повторный проезд той же ямы тем же пользователем в течение 2 часов (в радиусе 15 м) новую запись не создаёт. Серьёзность (ровно / заметно / жёстко) считается по превышению порога обнаружения для скорости удара. Ответ кэшируется на 15 с.
4. **Отображение.** Карта показывает подтверждённые дефекты цветными кругами (цвет и радиус — по силе), неподтверждённые — полыми маркерами.
5. **Доступ.** Вход по номеру телефона с одноразовым кодом: сервер выдаёт JWT-пару (access 24 ч + refresh 60 дней), клиент обновляет access автоматически. Телеметрия уходит с токеном, идентификатор пользователя берётся из JWT.
6. **Одометр.** Клиент считает пройденные метры на **любой** скорости, отсекает дрейф GPS и отправляет накопленное пачками; сервис атомарно прибавляет их к `users.total_distance_meters`. Детекция ударов требует ≥ 20 км/ч.
7. **Надёжность.** Неотправленные дефекты сохраняются в очереди на устройстве и досылаются; все HTTP-вызовы клиента с таймаутом.
8. **Статистика.** Профиль показывает километры, число дефектов, рейтинг и награды; бейдж сообщества («Топ N%») берёт серверный процентиль.

### 🎨 Дизайн-система «Полотно»

- **Две темы** — светлая «бетон» (`#EDEDEA`) и тёмная «асфальт» (`#08090A`). Это не инверсия: у каждой темы своя палитра. Токены живут в `PolotnoColors` (`ThemeExtension`) и доступны через `context.colors`.
- **Шрифты** — Unbounded (заголовки и цифры), Onest (интерфейс), JetBrains Mono (телеметрия). Подключены локально из `app/assets/fonts/`, интернет при запуске не нужен.
- **Полоса** (`RoadRibbon`) — дорога как непрерывная лента, окрашенная по качеству покрытия; поддерживает маркер «вы здесь».
- **Степени дефектов** — вместо S/M/L используются подписи **Ровно / Заметно / Жёстко** с порогами по `max_force`: `> 30` — жёстко, `> 20` — заметно, иначе ровно.
- **Переключение темы** — глобальный `ValueNotifier<ThemeMode>` в `main.dart`; выбор («Система / Светлая / Тёмная») делается в «Аккаунте» и сохраняется между запусками (`ThemeStore`).

## ⚡ Использование

### 🔌 Установка

**1. PostGIS**

```bash
cd backend
docker compose up -d db          # только БД на localhost:5432
```

**2. Сервис телеметрии**

```bash
cd backend

# Linux и macOS
export DATABASE_URL="postgresql://admin:password123@localhost:5432/road_pulse_db"
export JWT_SECRET="dev_secret"
go run ./cmd/api
```

```powershell
# Windows (PowerShell)
cd backend
$env:DATABASE_URL = "postgresql://admin:password123@localhost:5432/road_pulse_db"
$env:JWT_SECRET = "dev_secret"
go run ./cmd/api
```

Схема БД (расширение PostGIS и таблицы `telemetry`, `users`, `otp_codes`, `refresh_tokens`) применяется при старте автоматически. `DATABASE_URL` и `JWT_SECRET` обязательны: без них сервис не стартует.

**3. Мобильное приложение**

```bash
cd app
flutter pub get
flutter run
```

Адрес API захардкожен в `app/lib/api_service.dart`:

```dart
static const String baseUrl = String.fromEnvironment(
  'API_BASE_URL',
  defaultValue: 'http://64.188.74.105:8001/api/v1',
);
static const String apiUrl = '$baseUrl/telemetry';
```

Для локальной разработки замените хост на IP машины в той же сети, что и телефон (`localhost` с физического устройства не подойдёт). Обратите внимание: приложение ходит по HTTP, поэтому в `AndroidManifest.xml` включён `android:usesCleartextTraffic="true"`.

### 📡 API

| Метод | Путь | Авторизация | Назначение |
|-------|------|-------------|------------|
| `GET` | `/health` | — | Живость API и БД, версия PostGIS |
| `POST` | `/api/v1/auth/request-code` | — | Запросить одноразовый код на номер |
| `POST` | `/api/v1/auth/verify-code` | — | Проверить код, получить JWT-пару и профиль |

| `POST` | `/api/v1/auth/logout` | — | Отозвать refresh-токен |
| `GET` | `/api/v1/auth/me` | Bearer | Профиль со статистикой: пробег, дефекты, рейтинг, процентиль |
| `PATCH` | `/api/v1/auth/me` | Bearer | Обновить имя, город, клиренс |
| `POST` | `/api/v1/auth/sync-stats` | Bearer | Синхронизировать серию дней и награды; в ответе профиль со статистикой |
| `DELETE` | `/api/v1/auth/me` | Bearer | Удалить аккаунт, телеметрия анонимизируется |
| `POST` | `/api/v1/trips/start` | Bearer | Начать поездку |
| `POST` | `/api/v1/trips/finish` | Bearer | Завершить поездку: пробег, дефекты, доли качества покрытия |
| `GET` | `/api/v1/trips/last` | Bearer | Последняя завершённая поездка |
| `POST` | `/api/v1/telemetry` | опционально Bearer | Принять дефект (яму или участок плохой дороги) |
| `POST` | `/api/v1/telemetry/distance` | опционально Bearer | Прибавить пачку пройденных метров к пробегу пользователя |
| `GET` | `/api/v1/telemetry` | — | Список кластеров дефектов |
| `GET` | `/api/v1/telemetry/comments` | — | Комментарии к дефекту (`cluster_id`) |
| `POST` | `/api/v1/telemetry/comments` | Bearer | Добавить комментарий к дефекту |

**Вход**

```jsonc
// POST /api/v1/auth/request-code
{ "phone": "+79991234567" }
// → 200 { "status": "code_sent", "retry_after": 60 }

// POST /api/v1/auth/verify-code
{ "phone": "+79991234567", "code": "4821" }
// → 200 { "access_token": "...", "refresh_token": "...",
//         "user": { "id": "...", "phone": "...", "name": "...", "city": "...",
//                   "car_clearance": 0, "created_at": "..." },
//         "is_new_user": true }
```

Код живёт 5 минут, даётся не более 3 попыток, повторная отправка — через 60 секунд (после трёх неверных попыток — через 15 минут); в ответе кода нет, лимиты также действуют по IP (`429`); мастер-кода больше нет — принимается только выданный OTP. Отправкой занимается пакет `internal/sms`: при заданных `SMS_GATE_USER` и `SMS_GATE_PASSWORD` используется `GateProvider` (SMS Gateway for Android, сообщение уходит с SIM вашего телефона), иначе `MockProvider`, который печатает код в лог; в окружении `production` без этих переменных сервис не стартует. Если имя или город пустые, пользователь помечается как новый (`is_new_user: true`), и клиент ведёт его на шаг заполнения профиля.

**Приём дефекта**

Сервис отклоняет запросы со скоростью `< 20 км/ч` (ответ `400 Bad Request`) — так отсекаются дворы и пробки.

```json
{
  "user_id": "test_user_01",
  "latitude": 55.75,
  "longitude": 37.61,
  "speed_kmh": 40.0,
  "bump_force": 12.5,
  "defect_type": "rough_road",
  "infrastructure_type": "road",
  "trajectory": [
    {"lat": 55.7501, "lon": 37.6101, "timestamp": 1715000000.0},
    {"lat": 55.7502, "lon": 37.6105, "timestamp": 1715000005.0}
  ]
}
```

Поля `user_id`, `trajectory`, `event_time_ms` (время удара на устройстве, мс Unix), `client_event_id` (повтор с тем же значением не создаёт дубль), `heading_deg` (курс движения: выбирает сегмент дороги при привязке) и `accuracy_m` необязательны. Невалидный вход даёт `400`, превышение лимита — `429`, присланный, но недействительный токен — `401`. При валидном Bearer-токене `user_id` перезаписывается значением из JWT, иначе пустое значение заменяется на `anonymous`. `defect_type` по умолчанию `pothole`, `infrastructure_type` — `road`.

Ответ: `status`, `id`, `snapped_lat`, `snapped_lon`, нормализованный `bump_force` (формула `force × 20 / max(speed, 20)`), `severity` (1–3), `road_name`, `defect_type`, `infrastructure_type`, `geometry_type` (`Point` или `LineString`), `duplicate` (повтор события или та же яма от того же пользователя: клиент её не засчитывает).

**Пробег (одометр)**

Метры считает фоновый isolate — единственный владелец одометра; экран «Запись» получает счётчик поездки сообщением `TRIP:<метры>` и сам ничего не накапливает. Пачки уходят на сервер при накоплении ≥ 25 м либо ≥ 5 м за 20 секунд, плюс принудительный сброс при остановке службы. Шаг фиксируется на любой скорости; отбрасываются микроколебания (< 0.6 м), скачки (> 300 м) и позиции с точностью хуже 80 м.

```json
{ "distance_meters": 42.7 }
```

Ответ: `status`, `added_meters`, `total_distance_meters` — текущий итог пользователя в БД.

Без валидного Bearer-токена метры не отправляются (токен есть, но недействителен — `401`): клиент оставляет их в локальном буфере `pending_distance_meters` и сбрасывает на сервер после входа. Профиль берёт серверный `total_distance_meters` и прибавляет к нему неотправленный буфер, поэтому сервер остаётся источником правды, а локальные значения работают как оффлайн-фолбэк.

**Чтение кластеров**

Массив объектов: `cluster_id`, `lat`, `lon`, `max_force`, `severity`, `unique_users`, `total_hits`, `is_confirmed`, `defect_type`, `infrastructure_type`, `road_name`, `created_at`, а для линий — ещё и `lines` (каждая линия отдельно) и `coordinates` (одной ломаной, для старых клиентов).

- `pothole` — кластеры `ST_ClusterDBSCAN` (центроид, счётчики, `is_confirmed = unique_users >= 2 || total_hits >= 3`); `created_at` — максимальная метка времени внутри кластера.
- `rough_road` — линии кластеризуются тем же `ST_ClusterDBSCAN`, `cluster_id` смещён на `100000000`, а `lines` содержит `[[[lat, lon], …], …]` для отрисовки отдельных `Polyline`.
- Дата передаётся в `created_at`, поэтому фильтры «Сегодня / Неделя / Месяц» в ленте работают по реальным датам.

### 🔩 Окружение разработки

1. Клонируйте репозиторий и перейдите в нужную часть монорепозитория: `app/` — клиент, `backend/` — сервис.
2. Скопируйте переменные окружения сервиса (значения по умолчанию — только для разработки):

| Переменная | Обязательна | Назначение |
|------------|-------------|------------|
| `APP_ENV` | нет, по умолчанию `development` | Окружение: в `production` сервис требует боевые ключи и падает без них |
| `PORT` | нет, по умолчанию `8000` | Порт HTTP-сервера |
| `DATABASE_URL` | **да** | Подключение к Postgres; без неё сервис не стартует |
| `JWT_SECRET` | **да** | Ключ подписи access-токена; без него сервис не стартует |
| `OSRM_BASE` (или `OSRM_BASE_URL`) | нет, по умолчанию публичный OSRM | База OSRM для `match`/`nearest`; читаются оба имени |
| `SMS_GATE_USER`, `SMS_GATE_PASSWORD` | нет в dev, **да** в production | Логин и пароль из приложения SMS Gateway for Android; без них работает `MockProvider` (код в лог), а в `production` сервис не стартует |
| `SMS_GATE_URL` | нет | База API шлюза: по умолчанию облако `https://api.sms-gate.app/3rdparty/v1`; для локального режима — `http://<IP телефона>:8080` |
| `TRUST_PROXY` | нет, по умолчанию `false` | `true` за реверс-прокси (Caddy/nginx): IP для лимитов берётся из `X-Forwarded-For` |

3. Установите зависимости клиента: `cd app && flutter pub get`.

### 🚀 Развёртывание

Сервис и БД поднимаются одним compose-файлом:

```bash
cd backend
docker compose up -d                    # db (PostGIS 15-3.3) + api
```

| Сервис | Порт хоста | Особенности |
|--------|-----------|-------------|
| `api` | `8001 → 8000` | Multi-stage сборка из `Dockerfile`, ENV `APP_ENV`, `DATABASE_URL`, `PORT`, `OSRM_BASE`, `JWT_SECRET`, `SMS_GATE_URL`, `SMS_GATE_USER`, `SMS_GATE_PASSWORD`, `TRUST_PROXY` |
| `db` | `5432` | Том `road_pulse_data`, БД `road_pulse_db`, пользователь `admin` |

Перед публикацией задайте боевые значения через `.env` (шаблон — `backend/.env.example`): `docker-compose.yaml` требует `POSTGRES_PASSWORD`, `DATABASE_URL` и `JWT_SECRET` и не поднимется с пустыми переменными, а в `APP_ENV=production` сервис дополнительно не стартует без `SMS_GATE_USER` и `SMS_GATE_PASSWORD`. Образ сборки — `golang:1.25-alpine`, он совпадает с требованием `go.mod` (Go 1.25).

### ⚠️ Известные ограничения

- **Пороги детектора не откалиброваны.** Значения (`0.12 × км/ч`, ширина импульса, RMS 1.5 м/с², вращение 5 рад/с) подобраны по общим соображениям; их нужно подбирать по размеченным проездам. Исходная сила хранится в `telemetry.raw_bump_force`.
- **Комментарии привязаны к `cluster_id`** (для ям — `MIN(id)` точки кластера). Он стабильнее прежнего номера, но при слиянии кластеров комментарии «осиротеют». Нужен постоянный идентификатор дефекта.
- **Комментарии без модерации:** нет редактирования, удаления и жалоб; есть лимит 10 в минуту и 1000 символов.
- **SMS идут через телефон с SIM-картой** (SMS Gateway for Android): телефон должен быть включён и онлайн, оператор может ограничить массовую отправку. Для большой аудитории нужен коммерческий шлюз (реализовать новым `Provider`).
- **`docker-compose.yaml` по умолчанию запускает `APP_ENV=development`**: SMS уходит в лог, а защита от пустых `SMS_GATE_USER`/`SMS_GATE_PASSWORD` не срабатывает. Для боевого запуска задайте `APP_ENV=production` в `.env`.
- **Трафик по HTTP без TLS.** Токены и SMS-коды идут открытым текстом; нужен домен и HTTPS (тогда уберите `usesCleartextTraffic`).
- **Лимиты запросов хранятся в памяти процесса** и привязаны к IP (`RemoteAddr`). За реверс-прокси выставьте `TRUST_PROXY=true`, иначе все клиенты получат общий лимит.
- **Серия дней и награды приходят с клиента** (`sync-stats`) и входят в рейтинг; сервер лишь ограничивает их потолками (3650 и 30).
- **Процентиль считается на каждый `GET /auth/me`:** `PERCENT_RANK()` проходит по всем активным пользователям, кэша нет.
- **«Подвесок спасено» — эвристика** `ceil(дефекты × 0.15)`; формула продублирована на сервере и в оффлайн-фолбэке клиента.
- **Оффлайн-фолбэк статистики** считает рейтинг по локальным счётчикам, поэтому без сети цифры могут расходиться с серверными.
- **Фотографии дефектов не реализованы:** в карточках плейсхолдеры.
- **Публичный OSRM** (`router.project-osrm.org`) ограничивает частоту и не рассчитан на продакшен; при сбоях предохранитель отключает его на 30 с, и точки сохраняются без привязки к дороге.
- **Дубли пробега при потерянном ответе:** запрос `/telemetry/distance` не идемпотентен.
- Пороги силы (20/30) и скорости (20 км/ч) продублированы между клиентом (`constants.dart`) и сервером (`internal/service/telemetry.go`).
- **Пороги серьёзности (отношение к порогу 2.0 и 3.5) и ширины лежачего полицейского (1.5 м) стартовые**: их нужно подобрать по реальным проездам (`raw_bump_force` хранится). Те же числа продублированы в `constants.dart` и `internal/service/telemetry.go`.
- **Повторный проезд ямы в течение 2 часов не засчитывается**: так нельзя накрутить рейтинг, но и подтвердить яму одним человеком за день тоже нельзя.
- **`GET /telemetry` отдаёт все кластеры без `bbox`**: ответ растёт вместе с данными, кластеризация идёт по всей таблице.
- **Кнопки «Починили», «Она ещё тут», «Объехать» и «Поделиться» на карточке дефекта — заглушки**; ремонтируемые ямы пропадают только по сроку (180 дней).
- **Экран входа показывает «Тестовый код» и общее сообщение при любой ошибке запроса кода**, хотя сервер код больше не возвращает.
- Тесты покрывают расчёты, детектор, формулы сервиса и лимитер; тестов на роуты, SQL и интеграцию с OSRM нет. `widget_test.dart` проверяет артефакты Android.

## ❓ FAQ

**Яма не появилась на карте, почему?**
Дефект становится цветным маркером только после подтверждения: нужны ≥ 2 уникальных водителя или ≥ 3 попадания в одну точку. Всё остальное рисуется полыми маркерами.

**Я проехал яму, но запись не отправилась.**
Если сеть недоступна, событие остаётся в очереди на устройстве и уходит позже (до 24 ч).
Сервис принимает телеметрию только при скорости ≥ 20 км/ч. Дополнительно клиент игнорирует лежачие полицейские, а после срабатывания ставит детекцию на паузу.

**Где взять код из SMS?**
Пока не заданы `SMS_GATE_USER` и `SMS_GATE_PASSWORD`, код печатает `MockProvider` в лог сервиса (в окружении `production` сервис без них не запустится). Мастер-кода `1234` больше нет — принимается только выданный код.

**Как работают фильтры «Сегодня / Неделя / Месяц»?**
API отдаёт `created_at` каждого кластера, поэтому лента фильтрует дефекты по реальной дате попадания.

**Локальный API не подключается к БД.**
Проверьте, что Postgres поднят (`cd backend && docker compose up -d db`). Дефолтный `DATABASE_URL` в коде указывает на `road_pulse_db` и совпадает с compose, но переменная окружения его перекрывает — если вы задавали `DATABASE_URL` вручную, убедитесь, что имя базы и пароль совпадают.

**Считается ли пробег, если я иду пешком?**
Да. Одометр работает на любой скорости: шаг от 0.6 м фиксируется и на 3–5 км/ч. Детекция самих ударов по-прежнему включается только от 20 км/ч.

**Пробег стоит на месте, хотя я двигаюсь.**
Проверьте точность GPS: позиции с погрешностью хуже 80 м и шаги короче 0.6 м отбрасываются, чтобы стоящая машина не «накручивала» метры из-за дрейфа спутников.

**Километры в профиле не совпадают с сервером.**
Профиль показывает серверный `total_distance_meters` плюс неотправленный буфер с телефона, поэтому расхождение возможно только до следующей синхронизации. Без сети цифры считаются по локальным счётчикам.

**В «Аккаунте» неверная версия.**
Версия и номер сборки берутся из `pubspec.yaml` через `package_info_plus` при запуске приложения — после правки манифеста нужен полный перезапуск (`flutter run`), а не hot reload. Если плагин недоступен, показывается резервная строка из кода.

**Почему у меня бейдж «Новый участник» или «Топ 50%»?**
Бейдж берёт серверный `community_percentile` — место среди активных пользователей по рейтингу. Пока сервер не вернул процентиль (нет сети, либо у аккаунта ещё нет ни пробега, ни дефектов), используется фолбэк по порогам 50 / 200 / 400 / 800 / 1500 / 2500 очков.

**Как переключить тему?**
В «Аккаунте», раздел «Внешний вид»: «Система», «Светлая» или «Тёмная». Выбор сохраняется между запусками.
