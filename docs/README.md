# Дорожный пульс

Crowd-sourced карта дефектов дорожного полотна. Телефон в машине слушает акселерометр, привязывает удары к GPS и отправляет телеметрию; сервер нормализует силу удара по скорости, «прищёлкивает» точку к дороге, ведёт суммарный пробег и собирает общую карту подтверждённых дефектов.

## 🔰 О проекте

«Дорожный пульс» — клиент-серверная система из двух частей:

- **мобильное приложение** (Flutter, Android/iOS) — постоянно, в том числе в фоне, читает акселерометр и GPS, распознаёт удары и участки тряски и отправляет телеметрию на сервер;
- **сервис телеметрии** (Go + PostGIS) — принимает точки, привязывает их к дорожному графу, нормализует силу удара, кластеризует близкие попадания и отдаёт готовые дефекты для карты.

Общая карта строится совместно: два независимых водителя, попавших в одну яму, или три попадания в одну точку переводят дефект в статус подтверждённого.

### 🧭 Боль

- Водитель не знает, где на маршруте жёсткие ямы, пока не въедет.
- У города и сервисов нет «живой» карты дефектов покрытия — только разовые обходы и жалобы.
- Навигаторы оптимизируют время и пробки, но почти не учитывают качество асфальта.

### 💡 Решение

1. **Сбор.** Клиент в foreground-службе слушает `userAccelerometer`; при силе удара выше порога берёт GPS, скорость и буфер последних точек трека и отправляет телеметрию.
2. **Обработка.** Сервис нормализует силу удара по скорости, «прищёлкивает» точку к дороге через OSRM (`/match`, при неудаче — `/nearest`) и сохраняет геометрию в PostGIS (`POINT` для ям, `LINESTRING` для участков плохой дороги).
3. **Кластеризация.** Близкие удары объединяются (`ST_ClusterDBSCAN`, `eps ≈ 0.0003°`); кластер считается подтверждённым при **≥ 2 уникальных пользователях** или **≥ 3 попаданиях**.
4. **Отображение.** Карта показывает подтверждённые дефекты цветными кругами (цвет и радиус — по силе), неподтверждённые — полыми маркерами.
5. **Доступ.** Вход по номеру телефона с одноразовым кодом: сервер выдаёт JWT-пару (access 24 ч + refresh 60 дней) и профиль (имя, город, клиренс). Телеметрия уходит с токеном, идентификатор пользователя берётся из JWT.
6. **Одометр.** Клиент непрерывно считает пройденные метры на **любой** скорости (включая пешеходную 3–5 км/ч), отсекает дрейф GPS и отправляет накопленное пачками; сервис атомарно прибавляет их к `users.total_distance_meters`. Детекция самих ударов по-прежнему требует ≥ 20 км/ч, чтобы не ловить ложные срабатывания во дворах и пробках.
7. **Статистика.** Профиль показывает километры, число зачтённых дефектов, рейтинг и награды, пересчитывая их на клиенте; бейдж сообщества («Топ N%») выбирается по набранным очкам, а версия и номер сборки в «Аккаунте» читаются из манифеста приложения.

### 🎨 Дизайн-система «Полотно»

- **Две темы** — светлая «бетон» (`#EDEDEA`) и тёмная «асфальт» (`#08090A`). Это не инверсия: у каждой темы своя палитра. Токены живут в `PolotnoColors` (`ThemeExtension`) и доступны через `context.colors`.
- **Шрифты** — Unbounded (заголовки и цифры), Onest (интерфейс), JetBrains Mono (телеметрия). Подключены локально из `app/assets/fonts/`, интернет при запуске не нужен.
- **Полоса** (`RoadRibbon`) — дорога как непрерывная лента, окрашенная по качеству покрытия; поддерживает маркер «вы здесь».
- **Степени дефектов** — вместо S/M/L используются подписи **Ровно / Заметно / Жёстко** с порогами по `max_force`: `> 30` — жёстко, `> 20` — заметно, иначе ровно.
- **Переключение темы** — глобальный `ValueNotifier<ThemeMode>` в `main.dart`; переключателя в интерфейсе пока нет.

## ⚡ Использование

### 🔌 Установка

**1. PostGIS**

```bash
cd backend
docker compose up -d db          # только БД на localhost:5432
```

**2. Сервис телеметрии**

```bash
cd backend

# Linux и macOS
export DATABASE_URL="postgresql://admin:password123@localhost:5432/road_pulse_db"
export JWT_SECRET="dev_secret"
go run ./cmd/api
```

```powershell
# Windows (PowerShell)
cd backend
$env:DATABASE_URL = "postgresql://admin:password123@localhost:5432/road_pulse_db"
$env:JWT_SECRET = "dev_secret"
go run ./cmd/api
```

Схема БД (расширение PostGIS и таблицы `telemetry`, `users`, `otp_codes`, `refresh_tokens`) применяется при старте автоматически. Переменные можно и не задавать: дефолтный `DATABASE_URL` смотрит на ту же базу, что создаёт compose, а в dev-режиме `JWT_SECRET` подставляется из кода.

**3. Мобильное приложение**

```bash
cd app
flutter pub get
flutter run
```

Адрес API захардкожен в `app/lib/api_service.dart`:

```dart
static const String baseUrl = 'http://31.77.105.240:8001/api/v1';
static const String apiUrl = '$baseUrl/telemetry';
```

Для локальной разработки замените хост на IP машины в той же сети, что и телефон (`localhost` с физического устройства не подойдёт). Обратите внимание: приложение ходит по HTTP, поэтому в `AndroidManifest.xml` включён `android:usesCleartextTraffic="true"`.

| Метод | Путь | Авторизация | Назначение |
|-------|------|-------------|------------|

| `GET` | `/api/v1/telemetry` | — | Список кластеров дефектов |

| `POST` | `/api/v1/telemetry/comments` | Bearer | Добавить комментарий к дефекту |

**Вход**

```jsonc
// POST /api/v1/auth/request-code
{ "phone": "+79991234567" }
// → 200 { "status": "code_sent", "retry_after": 60 }

// POST /api/v1/auth/verify-code
{ "phone": "+79991234567", "code": "4821" }
// → 200 { "access_token": "...", "refresh_token": "...",
//         "user": { "id": "...", "phone": "...", "name": "...", "city": "...",
//                   "car_clearance": 0, "created_at": "..." },
//         "is_new_user": true }
```

Код живёт 5 минут, даётся не более 3 попыток, повторная отправка — через 60 секунд; мастер-кода больше нет — принимается только выданный OTP. Отправкой занимается пакет `internal/sms`: при заданном `SMS_API_KEY` выбирается `HttpProvider`, иначе `MockProvider`, который печатает код в лог; в окружении `production` без ключа сервис не стартует. Если имя или город пустые, пользователь помечается как новый (`is_new_user: true`), и клиент ведёт его на шаг заполнения профиля.

**Приём дефекта**

Сервис отклоняет запросы со скоростью `< 20 км/ч` (ответ `400 Bad Request`) — так отсекаются дворы и пробки.

```json
{
  "user_id": "test_user_01",
  "latitude": 55.75,
  "longitude": 37.61,
  "speed_kmh": 40.0,
  "bump_force": 12.5,
  "defect_type": "rough_road",
  "infrastructure_type": "road",
  "trajectory": [
    {"lat": 55.7501, "lon": 37.6101, "timestamp": 1715000000.0},
    {"lat": 55.7502, "lon": 37.6105, "timestamp": 1715000005.0}
  ]
}
```

Поля `user_id` и `trajectory` необязательны. При валидном Bearer-токене `user_id` перезаписывается значением из JWT, иначе пустое значение заменяется на `anonymous`. `defect_type` по умолчанию `pothole`, `infrastructure_type` — `road`.

Ответ: `status`, `id`, `snapped_lat`, `snapped_lon`, нормализованный `bump_force` (формула `force × 20 / max(speed, 20)`), `defect_type`, `infrastructure_type`, `geometry_type` (`Point` или `LineString`).

**Пробег (одометр)**

Метры считает фоновый isolate — единственный владелец одометра; экран «Запись» получает счётчик поездки сообщением `TRIP:<метры>` и сам ничего не накапливает. Пачки уходят на сервер при накоплении ≥ 25 м либо ≥ 5 м за 20 секунд, плюс принудительный сброс при остановке службы. Шаг фиксируется на любой скорости; отбрасываются микроколебания (< 0.6 м), скачки (> 300 м) и позиции с точностью хуже 80 м.

```json
{ "distance_meters": 42.7 }
```

Ответ: `status`, `added_meters`, `total_distance_meters` — текущий итог пользователя в БД.

Без валидного Bearer-токена метры не отправляются: клиент оставляет их в локальном буфере `pending_distance_meters` и сбрасывает на сервер после входа. Профиль берёт серверный `total_distance_meters` и прибавляет к нему неотправленный буфер, поэтому сервер остаётся источником правды, а локальные значения работают как оффлайн-фолбэк.

**Чтение кластеров**

Массив объектов: `cluster_id`, `lat`, `lon`, `max_force`, `unique_users`, `total_hits`, `is_confirmed`, `defect_type`, `infrastructure_type`, `created_at`, а для линий — ещё и `coordinates`.

- `pothole` — кластеры `ST_ClusterDBSCAN` (центроид, счётчики, `is_confirmed = unique_users >= 2 || total_hits >= 3`); `created_at` — максимальная метка времени внутри кластера.
- `rough_road` — линии кластеризуются тем же `ST_ClusterDBSCAN`, `cluster_id` смещён на `1000000`, а `coordinates` содержит `[[lat, lon], …]` для отрисовки `PolylineLayer`.
- Дата передаётся в `created_at`, поэтому фильтры «Сегодня / Неделя / Месяц» в ленте работают по реальным датам.

### 🔩 Окружение разработки

1. Клонируйте репозиторий и перейдите в нужную часть монорепозитория: `app/` — клиент, `backend/` — сервис.
2. Скопируйте переменные окружения сервиса (значения по умолчанию — только для разработки):

| Переменная | Обязательна | Назначение |
|------------|-------------|------------|
| `APP_ENV` | нет, по умолчанию `development` | Окружение: в `production` сервис требует боевые ключи и падает без них |
| `PORT` | нет, по умолчанию `8000` | Порт HTTP-сервера |
| `DATABASE_URL` | **да** | Подключение к Postgres; без неё сервис не стартует |
| `JWT_SECRET` | **да** | Ключ подписи access-токена; без него сервис не стартует |
| `OSRM_BASE` (или `OSRM_BASE_URL`) | нет, по умолчанию публичный OSRM | База OSRM для `match`/`nearest`; читаются оба имени |
| `SMS_API_KEY`, `SMS_SENDER` | нет в dev, **да** в production | При наличии ключа включается `HttpProvider`, иначе `MockProvider` с выводом кода в лог; в `production` без ключа сервис не стартует |

3. Установите зависимости клиента: `cd app && flutter pub get`.

### 🚀 Развёртывание

Сервис и БД поднимаются одним compose-файлом:

```bash
cd backend
docker compose up -d                    # db (PostGIS 15-3.3) + api
```

| Сервис | Порт хоста | Особенности |
|--------|-----------|-------------|
| `api` | `8001 → 8000` | Multi-stage сборка из `Dockerfile`, ENV `APP_ENV`, `DATABASE_URL`, `PORT`, `OSRM_BASE`, `JWT_SECRET`, `SMS_API_KEY`, `SMS_SENDER` |
| `db` | `5432` | Том `road_pulse_data`, БД `road_pulse_db`, пользователь `admin` |

Перед публикацией задайте боевые значения через `.env` (шаблон — `backend/.env.example`): `docker-compose.yaml` требует `POSTGRES_PASSWORD`, `DATABASE_URL` и `JWT_SECRET` и не поднимется с пустыми переменными, а в `APP_ENV=production` сервис дополнительно не стартует без `SMS_API_KEY`. Образ сборки — `golang:1.25-alpine`, он совпадает с требованием `go.mod` (Go 1.25).

### ⚠️ Известные ограничения

- **Комментарии привязаны к нестабильному `cluster_id`.** Для ям идентификатор кластера вычисляется на лету (`ST_ClusterDBSCAN … OVER ()`) и не гарантирует одну и ту же нумерацию между запросами: комментарий, оставленный к «кластеру N», после пересчёта может оказаться у другого дефекта. Стабилен только `rough_road` (`id + 1000000`). Нужен постоянный идентификатор дефекта в БД.
- **Комментарии без модерации.** Любой авторизованный пользователь может отправить любой текст; лимитов, редактирования, удаления и жалоб нет, а `author_name` берётся из тела запроса — подписаться можно чужим именем.
- **Боевой SMS-шлюз не реализован.** `internal/sms.HttpProvider` проверяет `SMS_API_KEY`, но вместо HTTP-вызова пишет код в лог; тихий фолбэк на `MockProvider` закрыт — в `production` без ключа сервис падает на старте. Остаётся подключить реальный шлюз.
- **`docker-compose.yaml` не задаёт `APP_ENV`**, поэтому контейнер работает в дефолтном `development`: SMS уходит в лог, а защита «в production без `SMS_API_KEY` не стартовать» не срабатывает.
- **Статистика синхронизируется через `PATCH /api/v1/auth/me`** — тот же запрос, что и редактирование профиля: серия дней и число наград записываются вместе с именем, городом и клиренсом.
- **Процентиль считается на каждый `GET /api/v1/auth/me`:** `PERCENT_RANK()` проходит по всем активным пользователям, кэша нет — при росте базы профиль станет тяжёлым запросом.
- **«Подвесок спасено» — эвристика** `ceil(дефекты × 0.15)`, а не измеренная метрика; формула продублирована на сервере и в оффлайн-фолбэке клиента.
- **Оффлайн-фолбэк статистики** считает рейтинг по локальным счётчикам, поэтому без сети цифры профиля могут расходиться с серверными.
- **Фотографии дефектов не реализованы:** в зависимостях нет камеры и выбора файлов, в карточках остаются плейсхолдеры.
- Точность одометра зависит от GPS: отсечки < 0.6 м и > 300 м вместе с порогом точности 80 м означают, что на пешеходной скорости часть шага может не учитываться.
- Пороги силы (20/30) и скорости (20 км/ч) продублированы между клиентом (`constants.dart`) и сервером (`internal/service/telemetry.go`): внутри каждой части они в одном месте, но не между ними.
- Адрес API захардкожен в клиенте как значение по умолчанию; переопределяется при сборке через `--dart-define=API_BASE_URL=…`.
- `app/test/widget_test.dart` проверяет артефакты только Android, а тестов на роуты и обработчики сервиса нет.

## ❓ FAQ

**Яма не появилась на карте, почему?**
Дефект становится цветным маркером только после подтверждения: нужны ≥ 2 уникальных водителя или ≥ 3 попадания в одну точку. Всё остальное рисуется полыми маркерами.

**Я проехал яму, но запись не отправилась.**
Сервис принимает телеметрию только при скорости ≥ 20 км/ч. Дополнительно клиент игнорирует лежачие полицейские, а после срабатывания ставит детекцию на паузу.

**Где взять код из SMS?**
Пока не задан `SMS_API_KEY`, код печатает `MockProvider` в лог сервиса (в окружении `production` сервис без ключа просто не запустится). Мастер-кода `1234` больше нет — принимается только выданный код.

**Как работают фильтры «Сегодня / Неделя / Месяц»?**
API отдаёт `created_at` каждого кластера, поэтому лента фильтрует дефекты по реальной дате попадания.

**Локальный API не подключается к БД.**
Проверьте, что Postgres поднят (`cd backend && docker compose up -d db`). Дефолтный `DATABASE_URL` в коде указывает на `road_pulse_db` и совпадает с compose, но переменная окружения его перекрывает — если вы задавали `DATABASE_URL` вручную, убедитесь, что имя базы и пароль совпадают.

**Считается ли пробег, если я иду пешком?**
Да. Одометр работает на любой скорости: шаг от 0.6 м фиксируется и на 3–5 км/ч. Детекция самих ударов по-прежнему включается только от 20 км/ч.

**Пробег стоит на месте, хотя я двигаюсь.**
Проверьте точность GPS: позиции с погрешностью хуже 80 м и шаги короче 0.6 м отбрасываются, чтобы стоящая машина не «накручивала» метры из-за дрейфа спутников.

**Километры в профиле не совпадают с сервером.**
Профиль показывает серверный `total_distance_meters` плюс неотправленный буфер с телефона, поэтому расхождение возможно только до следующей синхронизации. Без сети цифры считаются по локальным счётчикам.

**В «Аккаунте» неверная версия.**
Версия и номер сборки берутся из `pubspec.yaml` через `package_info_plus` при запуске приложения — после правки манифеста нужен полный перезапуск (`flutter run`), а не hot reload. Если плагин недоступен, показывается резервная строка из кода.

**Почему у меня бейдж «Новый участник» или «Топ 50%»?**
Бейдж берёт серверный `community_percentile` — место среди активных пользователей по рейтингу. Пока сервер не вернул процентиль (нет сети, либо у аккаунта ещё нет ни пробега, ни дефектов), используется фолбэк по порогам 50 / 200 / 400 / 800 / 1500 / 2500 очков.

**Как переключить тему?**
Тема читается из `themeModeNotifier` в `main.dart`; переключателя в интерфейсе пока нет — значение задаётся в коде.
